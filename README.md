# XR Tracking Visualization

Визуализация данных XR-трекинга: графики движения головы и рук,
3D-анимация скелета кистей.

Задача - изучить данные и представить их в понятном и наглядном виде.

## Что сделано

- Парсинг `trackingData_*.txt`
- Графики позиции головы и ладоней во времени
- 3D-анимация скелета обеих рук (26 суставов, стандарт OpenXR)


## Инструкция для Запуска
1. Нужно закинуть файл `trackingData_*.txt` в корень проекта
2. Запустить bash скрипт ниже

```bash
pip install -r requirements.txt
python main.py
```

## Допущения

Наложение трекинга на видео — приблизительное. Два допущения:

1. **Время.** Предположил, что видео и трекинг синхронизированы. 
    Точная синхронизация не проводилась —
   возможное расхождение до 0.40–1 секунд.
2. **Ракурс.** Стандартный ракурс matplotlib смотрит сзади —
   визуально левая и правая стороны меняются местами. Данные
   при этом корректные (правосторонняя OpenXR).


## Подход и наблюдение
Я открыл файл и увидел JSON-подобный формат: каждая строка —
один кадр, но позы записаны как строки с числами через запятую.
Разобрался, что поза — это 7 чисел (позиция x y z + кватернион),
а у каждой руки — 26 суставов (стандарт OpenXR).

Я выбрал визуализацию через графики и 3D-анимацию скелета рук.
Графики показывают движение головы и ладоней во времени,
а 3D-анимация наглядно демонстрирует разницу в активности
левой и правой руки.

На графиках видно, что левая рука почти неподвижна, а правая активно
двигается с амплитудой до 30–40 см.
Все значения отрицательные — это значит, что руки находились левее и ниже точки калибровки шлема

## Сложности

* Формат данных. Позы записаны как строки с числами через
запятую, а не как массивы. Десятичный разделитель — запятая,
а не точка. Понадобилась предварительная обработка перед
парсингом.

* Система координат. Сначала было непонятно, почему значения
отрицательные (X = −0.3, Y = −0.4). Оказалось, что (0,0,0) —
это точка калибровки, а не центр комнаты. Пришлось разбираться
в осях (правосторонняя система OpenXR).
  
* Ракурс в 3D. В 3D-анимации левая рука отображалась
  справа. Оказалось, это особенность ракурса matplotlib, а не ошибка в данных.
